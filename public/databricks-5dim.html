Supervisor AgentAgentBricks · OrchestrationGA
No-code orchestration layer that routes user intent to sub-agents (Genie, Knowledge Assistant, UC Function Tools). The brain of FFF's OS&D agent network — 10+ days → 1–3 minutes.
UI — No-Code Setup
  1. Navigate Workspace → AI & BI → AI Agents
  2. Click Create Agent → Supervisor Agent
  3. Name the agent; select a UC catalog/schema to register it in
  4. Add sub-agents from the palette: Genie Agents, Knowledge Assistant, UC Function Tools
  5. Set confidence threshold (0–1 float) for routing decisions
  6. Click Deploy — generates a serving endpoint + MLflow trace logging automatically
  7. Expose via Review App for testing, or Teams integration for production

Medallion Layer MappingSupervisor sits above Gold layer — queries Gold Delta tables via Genie Agent (structured), Gold Volumes via Knowledge Assistant (unstructured). Bronze/Silver are upstream and invisible to the agent at query time.
  • What is OBO authentication and why does it matter for Supervisor Agent?
    On-Behalf-Of (OBO) passes the end-user's identity token — not a service principal — to all downstream tool calls. UC row-level security and column masks enforce permissions based on who is asking, not who the agent runs as. For FFF: a warehouse manager can only query their region's inventory via the Warehouse Agent; an exec sees all. Without OBO you'd replicate row-level permissions in every sub-agent separately.
  • How does the Supervisor route to the right sub-agent?
    An LLM intent classifier reads the user's message against the registered descriptions of each sub-agent. Confidence scoring determines whether to answer or return uncertainty. The descriptions you write ARE the routing logic — make them semantically distinct and specific (e.g. "Call this when user asks about SAP order status or fulfillment records" vs "Call this when user asks about drug SOP or handling procedures").
  • How do you debug a mis-routed Supervisor query?
    Inspect the MLflow 3 trace in system.agent_traces: the span tree shows the classification decision, which sub-agent was called, inputs/outputs, confidence score. Use the Review App for interactive testing. Improve routing by editing sub-agent descriptions to be more semantically distinct.
  • Supervisor Agent vs custom LangChain agent — when would you choose each?
    Supervisor Agent: managed, no-code, UC-governed natively, built-in OBO auth, MLflow tracing, Teams integration — right for enterprise governance-first deployments like pharma distribution. LangChain: more flexibility, custom orchestration logic, multi-provider LLMs, but requires manual UC integration and auth logic. SA answer: for FFF's regulated environment, Supervisor Agent reduces implementation risk and provides auditability out-of-the-box.

  • A Genie Agent gives wrong answers about shipment status. What do you investigate first?
    Column and table descriptions in Unity Catalog. Check if ambiguous columns (status codes, date fields, quantity units) have clear COMMENT text. Second: add trusted assets — pre-validated SQL for the most common questions. Third: run Genie Benchmarks on a test set and measure accuracy. Only after metadata is comprehensive should you consider the warehouse type or query complexity as factors.
  • When would you use Genie vs a direct SQL dashboard?
    Genie for ad-hoc NL exploration by non-technical users ("which drivers had the most OS&D claims in Q3?"). SQL dashboards for known, fixed KPIs with scheduled refresh. Genie is not a replacement for dashboards — it's a dynamic query layer on top of the same Gold tables that power your dashboards.
  • How does Genie handle row-level security?
    Via OBO — it inherits the authenticated user's UC permissions. Row filters defined as SQL UDFs on the Gold table apply transparently when Genie runs its generated query. The agent never sees data the user isn't authorized to see.

What Happens Under the HoodKnowledge Assistant automatically: (1) ingests docs from UC Volumes, (2) chunks them semantically, (3) embeds using Databricks Foundation Models, (4) stores in a managed AI Search index, (5) performs hybrid retrieval at query time, (6) generates answers with citations to source docs in UC. You own the source files; Databricks manages the entire pipeline.

  • When does Supervisor route to Knowledge Assistant vs Genie Agent?
    Genie Agent: structured data questions (inventory counts, order status, dates — queryable via SQL). Python or SQL functions registered in Unity Catalog that the Supervisor Agent calls as tools. Enables integration with SAP, FedEx, Salesforce APIs. The action layer of FFF's agent network.
SQL Function Registration
SQL · Register a UC Function Tool with routing-ready COMMENT
CREATE OR REPLACE FUNCTION
  prod.supply_chain.get_sap_order_status(
    order_id STRING COMMENT 'SAP order number, format SAP-YYYY-NNNN'
  )
RETURNS STRING
COMMENT 'Returns SAP fulfillment status for an order.
Call when user asks about order status, shipment progress, or SAP records.'
LANGUAGE PYTHON AS $$
  import requests
  secret = dbutils.secrets.get("sap-creds", "api-token")
  resp = requests.get(
    f"https://sap-api.fff.internal/orders/{order_id}",
    headers={"Authorization": f"Bearer {secret}"}
  )
  return resp.json()["status"]
$$;

GRANT EXECUTE ON FUNCTION

TO `supervisor-agent-sp`;

  • Why register tools in UC rather than defining them inline in the agent?
    UC registration gives versioning, access control (GRANT/REVOKE EXECUTE), lineage tracking, discoverability, and reuse across multiple agents. The same get_sap_order_status function can be called by the Supervisor Agent AND directly by a Workflow job AND exposed to Teams via a different agent — without duplicating code. It's the single source of truth for that integration capability.
  • How do you handle secrets in UC function tools?
    Use Databricks Secrets: dbutils.secrets.get(scope="sap-creds", key="api-token"). Never hardcode credentials in function bodies. The function's service principal (or user via OBO) must have GET permission on the secret scope. Secrets are encrypted at rest and never appear in MLflow traces or audit logs.

  • How do you promote a model from dev to prod in UC Model Registry?
    Register a new version in the prod catalog (prod.ml.osd_classifier) — models are not moved or transitioned. Your CI/CD pipeline: (1) train in dev, register in dev.ml.*, (2) run evaluation, (3) if passing, register same artifact in prod.ml.* using copy_model_version(), (4) set @champion alias on the new version. Model Serving endpoint reads @champion automatically — no restart, no URL change.
  • What does mlflow.evaluate() measure for RAG and why is faithfulness most critical for pharma?
    Faithfulness: does the answer stay within the retrieved context (no hallucinations)? Context precision: is the retrieved context relevant? Answer relevance: does the answer address the question? Context recall: was all relevant context retrieved? For pharma distribution: faithfulness is most critical — a hallucinated drug dosage, availability status, or handling procedure is a patient safety risk and potential regulatory violation.
  • What's the difference between MLflow 3 tracing and earlier versions?
    MLflow 3 introduces hierarchical span trees (not just flat run logs) — each agent call produces a tree of spans: supervisor routing, sub-agent calls, tool invocations, each with inputs/outputs and timing. Traces are stored as Delta tables in UC (system.agent_traces) making them queryable via SQL. Earlier MLflow only had flat run metrics — not suitable for debugging multi-step agent pipelines.

  • When do you use provisioned throughput vs serverless Model Serving?
    Provisioned throughput: steady-state, high-volume inference with latency SLA (e.g. FFF's real-time OS&D classifier responding under 500ms p99). Serverless: bursty or unpredictable traffic where scale-to-zero saves cost (e.g. an overnight reporting model). Cost crossover: roughly when utilization exceeds 60% continuously. For LLMs: provisioned throughput guarantees tokens-per-second; serverless may queue under load.
  • How do you do zero-downtime model promotion with Model Serving?
    Use traffic splitting: 90% to @champion, 10% to @challenger. Monitor metrics for both. The endpoint automatically shifts 100% traffic — no new endpoint URL, no downtime. Lakehouse Monitoring tracks prediction drift across both versions during transition.
Unity CatalogData GovernanceGA
Account-level metastore providing unified governance. Three-level namespace (catalog.schema.table), ABAC with row filters and column masks as SQL UDFs, automatic column-level lineage.
SQL · Core UC Governance Operations
-- Three-level namespace
CREATE CATALOG IF NOT EXISTS prod;
CREATE SCHEMA IF NOT EXISTS prod.supply_chain;

-- Row-level security: SQL UDF-based row filter
CREATE FUNCTION prod.security.shipment_region_filter()
RETURNS BOOLEAN
RETURN is_account_group_member('global-ops')
    OR current_user() = region_owner;

ALTER TABLE prod.supply_chain.shipments
  SET ROW FILTER prod.security.shipment_region_filter() ON ();

-- Column mask: hide patient ID except for PHI-access group
CREATE FUNCTION prod.security.mask_patient_id(patient_id STRING)
RETURNS STRING
RETURN CASE WHEN is_account_group_member('phi-access')
    THEN patient_id ELSE 'REDACTED' END;

ALTER TABLE prod.supply_chain.shipments
  ALTER COLUMN patient_id SET MASK prod.security.mask_patient_id();

-- Grants
GRANT SELECT ON TABLE prod.supply_chain.shipments TO `data-analysts`;
GRANT USE CATALOG ON CATALOG prod TO `data-analysts`;

  • Hive metastore vs Unity Catalog — key differences?
    Hive metastore: workspace-level (2-level: schema.table), no cross-workspace governance, no row-level security, no column masking, no lineage. UC: account-level (3-level: catalog.schema.table), shared across workspaces, ABAC with row filters and column masks as SQL UDFs, automatic column-level lineage, governs models, functions, volumes, and agents too. For FFF with multiple workspaces: UC is the only option for unified governance.
  • How many metastores can you have per cloud region?
    One metastore per region per Databricks account. Common exam question. Multiple catalogs within one metastore is fine, but not multiple metastores in the same region. Multi-region deployments get one metastore each; use Delta Sharing for cross-region data access.
  • Why does column-level lineage matter for pharma compliance?
    UC automatically tracks which upstream columns contributed to each downstream column, across notebooks, jobs, and DLT pipelines. For a pharma distributor: if a compliance audit asks "where does patient_id in this report come from?", lineage traces it back to the Bronze source system. Critical for HIPAA compliance and FDA/DEA audit trails — no manual documentation needed, automated and always current.

  • How does Delta Lake achieve ACID without a traditional lock manager?
    Optimistic concurrency control via the transaction log (_delta_log/). Each write appends a new JSON commit entry. On conflict (two concurrent writers), the second writer checks if the first's changes overlap with its read set. No overlap (different partitions) → both commits succeed. Overlap → one is rejected and must retry. This is optimistic — assumes conflicts are rare, true for typical Lakehouse workloads where writers are partition-separated.
  • Z-ORDER vs Liquid Clustering — when do you choose each?
    Z-ORDER: stable, works on all Databricks versions, requires OPTIMIZE after significant loads, columns fixed at creation. Liquid Clustering (2024+): auto-managed, no explicit OPTIMIZE needed, change clustering columns without a full rewrite. SA recommendation: prefer Liquid Clustering for new tables on current runtime; Z-ORDER for legacy tables or compatibility requirements.

  • What is Reciprocal Rank Fusion and why does it work for hybrid search?
    RRF merges two ranked lists (BM25 results + ANN results) using: score = sum(1/(k + rank_i)) for each list, k=60 default. A document ranked high in both lists scores highest. RRF works because it's rank-based, not score-based — it doesn't require calibrating absolute similarity scores from two different metrics. Result: a document that's #1 BM25 match AND #3 ANN match scores higher than one that's #1 in only one list.
  • Delta Sync vs Direct Vector Access — when do you use each?
    Delta Sync: your source data is in a Delta table — Databricks handles embedding generation and index updates automatically via CDF. This is 90% of cases. Direct Vector Access: you compute embeddings yourself (proprietary model, pre-computed elsewhere) and push vectors directly to the index. Use when embedding generation must happen outside Databricks or you need exact control over the chunking and embedding pipeline.

  • What is Repair Run and when is it valuable?

Critical for long Lakehouse pipelines where reprocessing Bronze ingestion is expensive.

  • What is the difference between data drift and prediction drift?
    Data drift: the distribution of input features changes (e.g. FedEx shipping patterns shift after a carrier partnership change — delivery times cluster differently). Prediction drift: the model's output distribution changes (more shipments flagged as OS&D risk). You need both: data drift tells you WHY model behavior may change; prediction drift tells you the model IS changing. For pharma: prediction drift could mean real-world OS&D rates are genuinely increasing OR the model is degrading — both require investigation.
  • How do Lakehouse Monitoring metrics connect to model retraining?
    Drift metrics land in prod.monitoring.shipments_drift_metrics (Delta table). A SQL Alert monitors it: when js_divergence exceeds threshold, it fires a webhook triggering a Workflow. The Workflow: (1) retrains on recent labeled data, (2) registers new MLflow version in prod.ml.* as @challenger, (3) evaluates vs @champion, (4) promotes @challenger to @champion if metrics improve. Serving endpoint reads @champion — no restart needed. This is the full MLOps loop, entirely within Databricks.
