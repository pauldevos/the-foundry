The local-first Databricks Apps workflow

Use VS Code as the authoring and AI-assistant surface; use Databricks as the governed execution plane. The productive loop is local process/debugger → Databricks Connect for Spark/SQL → apps run-local for app proxy behavior → Bundle deploy for workspace verification.

The five questionsFree Edition-aware
This is the flow to run today. Free Edition can prove the loop, but it cannot simulate every enterprise identity/network/scale control.

GUI setup once
  1. Install the Databricks VS Code extension, Python/Node extensions and a debugger.
  2. Create a workspace OAuth profile with databricks auth login --host https://<workspace> --profile dbx-free.
  3. In the workspace, create a small app from a template; use Sync files to pull the generated app.py/app.yaml into the repo.
  4. Inspect app resources and copy their stable keys into configuration—not tokens or workspace-specific secrets.
  5. Run the app locally, then deploy a dev target from the bundle and compare logs/health with the local behavior.
AI assistant operating rules
  • Start each task with the architecture contract: inputs, outputs, resource keys, auth model, failure behavior and acceptance tests.
  • Ask for a small patch plus tests; review every generated dependency and permission.
  • Never paste OAuth tokens, client secrets, private documents or production traces.
  • Have the assistant explain Databricks-specific claims against a linked official doc before adopting them.

Limits and mitigations
ConcernMitigation
Version couplingPin Python and Databricks Connect versions to the serverless/runtime compatibility matrix; test upgrades separately.
Local vs hosted driftUse run-local for proxy/env behavior, Connect for Spark execution, and a disposable dev deployment for final integration.
AuthU2M OAuth for humans; service-principal M2M/OIDC for CI. Use environment/config injection; never commit credentials.
AppKitUse when React + Databricks typed queries/components accelerate delivery. Use plain React when custom UX, routing, or vendor ecosystem outweighs the acceleration.
Testing AIMock model calls for unit tests; use deterministic golden datasets and explicit eval budgets for integration tests.
CLI availabilityFree Edition/workspace features can lag enterprise previews. If a command or resource is unavailable, document the enterprise equivalent rather than changing architecture silently.
