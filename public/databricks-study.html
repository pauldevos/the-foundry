Databricks Architect: the five decisions to know cold

This is the fast path for a senior engineer designing 1–3 month AI applications on Databricks. Each deep dive answers the same five questions: what it does, when to use it, GUI build, code/deploy path, and limits/security/cost tradeoffs. Documentation is the source of truth; the pages turn it into architecture decisions and build sequences.

01 · Databricks Apps

App identity, user authorization, resources, runtime limits, AppKit vs React, API and embedding.

02 · AI services

AI Search, Knowledge Assistant, Genie Agents, Agent Bricks, Model Serving, evaluation and external model comparisons.

03 · Deployment + CI/CD

Declarative Automation Bundles, GitHub OIDC, promotion, health checks, rollback, and app-specific failure modes.

04 · VS Code development flow

CLI profiles, Databricks Connect, apps run-local, AppKit, AI assistants, tests, and the Free Edition boundary.

05 · Identity + governance

App service principals, OBO/user authorization, OAuth, Unity Catalog, secrets, network and audit decisions.
